# SJTUFitMan · 交大健身房助手

在自己的 Windows 电脑上运行，登录交大体育平台、查询预约余量、创建待付款订单，并用邮件提醒付款。每位同学使用自己的账号、邮箱和本地配置；程序不会自动付款，也不调用 LLM。

## 功能

| 页面 | 用途 |
| --- | --- |
| 自动预约 | 一个表单选择“指定日期候补”或“每日12点开抢”，保存并启动轮询 |
| 记录 | 查看本机订单、成功通知状态，核查异常订单、重试漏发邮件 |
| 设置 | 保存账号、自动或手动登录，配置邮箱并发送测试邮件 |

支持 **1 小时或连续 2 小时**。两小时要求同一场地的两个小时都有余量，合为一张订单。登录验证码使用本地 ddddocr，预约滑块使用本地 OpenCV；失败时转手动处理。

## 普通用户：下载发布版

前往 [GitHub Releases 下载最新版](https://github.com/pioneerLu/SJTUFitMan/releases/latest)。普通用户选择页面附件中的 Windows ZIP，解压后即可运行。

没有VS Code或Python也可以使用。下载发布附件 **`SJTUFitMan-v版本号-windows-x64.zip`**，将整个文件夹解压到桌面或“下载”目录，双击 **`交大健身房助手.exe`**。电脑需安装Chrome或Microsoft Edge其中一种；账号、邮件、日期和时段均通过界面设置。

发布版自带Python运行环境、ddddocr模型、OpenCV和Playwright驱动。首次启动在应用目录创建自己的 `config/config.toml`，运行记录保存在 `.local/`。个人配置写在程序目录外层，不写入exe；请保留完整解压目录。

本地生成的发布包位于 `dist/`，维护者可按[打包说明](docs/RELEASE_GUIDE.md)生成。GitHub 的 **Source code** 压缩包是开发者源码，普通用户请下载名称为 `SJTUFitMan-v版本号-windows-x64.zip` 的附件。

## 开发者：源码安装与启动

当前支持 **Windows、Python 3.13（64 位）、Google Chrome和Microsoft Edge**。使用项目独立 `.venv`，依赖版本固定在 `requirements.txt`。

登录后台在点击登录按钮后才启动浏览器驱动。关闭软件时会等待当前操作和登录浏览器完成清理；看到“正在关闭”时请稍候，窗口会自行退出。下拉选项列表使用自己的滚轮处理，页面滚动不会干扰选项选择。

自动登录会等待jAccount页面跳转完成，账号、密码输入框可见且可编辑后才填入；页面等待最长30秒。加载超时会提示重新打开登录页或手动登录。登录诊断记录包含实际使用的浏览器，不包含账号密码。

1. 安装 [Python 3.13](https://www.python.org/downloads/windows/)、[Chrome](https://www.google.com/chrome/) 或 [Microsoft Edge](https://www.microsoft.com/edge)其中一种，以及[PowerShell 7](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)。Python安装时勾选加入PATH。
2. 克隆仓库，或在仓库页面选择 **Code → Download ZIP** 并解压。
3. 在项目文件夹打开 PowerShell 7，执行：

   ```powershell
   pwsh -NoProfile -File .\scripts\setup_env.ps1
   ```

   如果有多个 Python，可指定 Python 3.13 的路径：

   ```powershell
   pwsh -NoProfile -File .\scripts\setup_env.ps1 -BasePython 'C:\路径\Python313\python.exe'
   ```

4. 双击根目录唯一入口 **`交大健身房助手.pyw`**。也可在终端启动：

   ```powershell
   .\.venv\Scripts\pythonw.exe .\交大健身房助手.pyw
   ```

普通启动显示自动预约表单，点击“保存并启动”后才运行轮询。已有成功订单的漏发邮件会由后台补发；没有成功记录时不会发送邮件。浏览器使用本机Chrome或Edge，无需另外下载Playwright Chromium。

在 **设置 → 账号与登录 → 使用浏览器** 选择“自动选择”“Google Chrome”或“Microsoft Edge”。选择后自动保存到统一配置，登录、恢复会话、查询时段、候补和每日预约共用。自动模式优先Chrome，未安装或仅在启动阶段失败时尝试Edge；明确选择时遵从该选择，缺少浏览器会提示安装或重新选择。两个浏览器均启动独立窗口，可复用助手保存的体育平台会话。已打开的窗口在下一次启动时切换，预约进行期间不能修改浏览器设置。

## 统一个人配置

所有用户设置集中在 **`config/config.toml`**。首次安装或启动时，程序会从 [config/config.example.toml](config/config.example.toml) 创建个人副本；也可以手动复制样例。

| 配置区块 | 内容 |
| --- | --- |
| `[ui]` | 上次使用的自动预约计划类型 |
| `[auth]` | jAccount 账号密码、会话文件路径 |
| `[site]` | 体育平台地址与时区 |
| `[polling]` / `[booking]` | 每日任务启用状态、项目、候选时段、场地和轮询限制 |
| `[waitlist]` | 项目、固定候补日期/时段、立即或定时开始、查询间隔 |
| `[mail]` | 发信邮箱、收件邮箱、SMTP 授权码和邮件重试设置 |

账号可以在 **设置 → 账号与登录 → 保存账号到本地配置** 中保存；两种自动预约计划和邮箱设置也保存到同一文件。密码和授权码在本机配置中为明文，请保管自己的电脑和文件。样例不包含任何个人账号、邮箱或授权码。

之后只使用这一份个人配置，安装和再次启动都会保留已填写的设置。程序不创建配置备份。

## 第一次使用

1. 在 **设置 → 账号与登录** 填写账号密码，选择“自动登录”或“浏览器手动登录”。成功后自动保存会话；账号密码须显式点击保存。手动登录或自动识别失败时会展开验证码辅助区域：显示完整原图并放大，支持手动输入或本地识别；刷新会替换图片并清空旧答案。验证码在浏览器中变化后，需重新显示图片再输入。
2. 在 **设置 → 邮箱通知** 填写发件邮箱、邮箱授权码、收件邮箱，保存后发送测试邮件。QQ邮箱通常沿用默认服务器设置；其他服务商或特殊SMTP用户名可展开高级设置。授权码不是邮箱登录密码。
3. 在 **自动预约** 选择计划、项目、日期和时段，设置查询间隔，点击 **保存并启动**。切换计划保留各自的表单选择；保存当前计划不会覆盖另一种计划或登录、邮箱设置。

两种自动预约计划都在核实抢到后发送成功通知，无论订单待付款还是已支付。成功事件先写入本机记录，再尝试发信；邮件配置缺失时也保留通知。软件运行期间自动按邮件配置重试，重新打开软件会恢复漏发的成功记录，包括旧版本的成功订单，补发不要求重新登录，也不会再次预约。邮件明确说明确认时的状态，订单当前是否待付款、过期或取消以体育平台为准。模拟和未核实的预约不发成功通知。

临时发送失败或发送结果不明时按 `mail.retry_interval_seconds` 和 `mail.max_attempts` 重试；结果不明时重试可能产生重复邮件。达到次数上限或授权码无效时会显示需要处理，修正邮箱设置后可点击 **重试未发出的邮件**。软件需保持运行；关闭后未发出的通知保留到下次启动。邮箱服务器接受邮件不保证进入收件箱，请检查垃圾邮件。

### 每日12点开抢

在自动预约页切换到“每日12点开抢”，选择项目，刷新网站日期和时段，添加一小时或连续两小时的候选并调整优先顺序。切换项目会清空旧项目的候选时段和指定场地。日期自动显示开抢日的七天后，无需手动填写。

设置查询间隔和停止条件，点击“保存并启动”即可保存、启用并启动每日计划。停止条件可选“持续指定时长”或“指定截止时间”，用小时、分钟和日期下拉选项设置。每天北京时间12:00预约七天后的时段；12:00前只等待本机时间；成功后停止当天查询、发成功通知。

每日查询间隔允许20～600秒。持续时长是每轮从12:00起的上限，可设1分钟至24小时，当天结束后次日继续；指定截止时间是整个每日任务的截止点，到期后不再开始下一天的预约。新界面按时间上限停止，保存每日计划时将额外查询次数上限设为0；旧配置中显式设置的 `max_checks` 仍由后台尊重。

### 指定日期候补

在同一个自动预约表单切换到“指定日期候补”，选择项目、今天至七天后的日期和一小时或连续两小时时段；选择立即开始或定时开始，设置查询间隔，点击“保存并启动”。刷新时不会把尚未开放的目标日期偷偷改成另一日。指定日期计划与每日计划分别保存，查询间隔允许20～600秒，不受每日次数和时间窗口限制。

候补停止条件可选 **持续指定时长、指定截止时间或直到目标时段开始**。时长从计划启动时刻计算，包含登录耗时；立即启动从本次任务开始计时，定时启动从所设开始时间计时，查询和冷却不会使上限顺延。成功、手动停止、设定上限及目标时段开始，以最早发生的条件为准。例如 `18:00-20:00` 最晚在当天18:00结束。成功后结束此次候补，发付款提醒，不启动次日候补。

截止后不再开始下单；已发出的请求会先核实，抢到仍发送通知。候补时长支持1分钟至8天，实际截止不会晚于目标时段开始。

两种模式的查询间隔从上一次查询结束后计算。查询间隔并不等于网站所有请求的间隔，登录、页面初始化、验证码及订单核查还会产生请求。登录失效、限频、已有待付款订单或下单结果不明时停止并提示处理；普通查询超时会退避，连续三次后停止。

### 付款与关闭

付款提醒包含日期、时段、金额、订单号和体育平台入口。请尽快在体育平台 **个人订单** 中核对并自行付款，期限以平台显示为准。

电脑需保持开机、联网且不睡眠。关闭窗口会请求停止轮询，已发出的下单先完成核实后退出。成功记录先保存再发邮件；重启、邮件失败或修改频次不会导致重复预约。邮件服务器接受不保证收件箱已送达，请检查垃圾邮件。

网站拒绝下单时，预约结果会显示网站的具体提示、HTTP 状态和错误码；轮询也会显示这些信息并停止下单。可在本机 `.local/booking/last-order.json` 或 `.local/booking/journal.json` 的 `server_feedback` 中查看，记录不包含完整响应、账号密码或会话令牌。较早版本的拒绝记录没有保存具体提示，无法事后恢复。

## 项目结构

```text
交大健身房助手.pyw          # 唯一桌面入口
config/
  config.example.toml       # 可提交的空白样例
  config.toml               # 个人设置，Git 忽略
scripts/
  app_ui.py                 # 统一窗口与任务协调
  automatic_ui.py           # 两种计划共用的自动预约表单
  records_ui.py              # 订单与邮件记录、异常核查
  settings_ui.py             # 账号登录、邮箱设置
  desktop_worker.py          # 隐藏后台进程、页面生命周期与滚动容器
  configuration.py          # 统一配置读写与初始化
  login.py / login_flow.py   # 登录与会话
  booking_flow.py            # 订单、验证码和下单校验
  poll_runner.py / poll_settings.py
  captcha.py / slider.py     # 本地验证码
  mail_notice.py             # 付款提醒和邮件去重
  setup_env.ps1              # 安装独立环境
  check_release.py           # 发布文件与个人信息检查
  build_release.py           # 打包、发布版自检、生成ZIP和校验文件
packaging/                  # Windows打包定义
docs/                       # 操作说明与历史验证报告
tests/                      # 本地模拟测试
.local/                     # 会话、验证码图片、订单、邮件等私有运行记录
.github/workflows/          # GitHub 自动测试
```

各页面复用执行模块，每次只运行一个登录、预约或邮件操作；进程间还通过文件锁限制重复任务。

## 开发与测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
.\.venv\Scripts\python.exe scripts\check_ui.py
.\.venv\Scripts\python.exe scripts\manage_config.py check
.\.venv\Scripts\python.exe scripts\check_release.py
```

Python 测试使用模拟浏览器、模拟邮件和临时配置，不访问体育平台，不创建真实订单。安装 Node.js 后还可运行：

```powershell
node --test tests\appointment_snapshot.test.cjs tests\checkout_snapshot.test.cjs tests\export_session.test.cjs tests\two_hour_frontend.test.cjs
```

最后一项历史前端测试依赖不随仓库分发的 `.inspection/` 缓存，干净检出时自动跳过。GitHub 工作流只运行本地测试，不需要个人账号或邮箱授权码。

真实网站的登录、只读查询和前端模拟已有历史验证；真实预约下单尚未完成学校服务器的端到端验证。当前版本不能保证抢到名额。操作详情见 [登录说明](docs/LOGIN_GUIDE.txt)、[预约说明](docs/BOOKING_GUIDE.txt)、[轮询说明](docs/POLLING_GUIDE.txt) 和 [验证码历史实测](docs/CAPTCHA_REPORT.txt)。

## 提交到 Git

提交代码、样例、依赖文件和文档。`.gitignore` 排除个人配置、`.local/`、`.venv/`、网站缓存和临时文件；`check_release.py` 会检查工作文件和 Git 暂存内容，并在本地比对是否含有个人配置中的账号或授权码，只报告文件名，不输出秘密内容。

不要强制添加被忽略的个人文件，也不要把整个工作目录压缩后分享。使用 GitHub 的源代码下载或 `git archive` 可只导出已提交文件。每位同学首次运行后会生成自己的配置和会话，互不共用账号。
